# Script reference

Every script prints one JSON object to stdout and exits with one of the codes listed at the end. Run each with `"${SNAPTRADE_PY:-python3}" skills/<skill>/scripts/<script>.py ...` from the plugin root, or ask Claude and let the skill run it. The `python x.py < input.json` scripts are pure math over a JSON object on stdin; their input contract is in each script's docstring.

## installer

| Script | What it does |
|---|---|
| `install.js` | `node install.js [--all \| --skills a,b \| --without x,y] [--target DIR] [--snaptrade-client-id ID --snaptrade-consumer-key KEY] [--edgar-user-agent "app me@x"] [--env-file PATH] [--no-link] [--no-smoke] [--json] [--plain] [--dry-run] [--yes] [--uninstall [--purge-data]]` — guided installer with no flags; subset install with dependencies, `.env`, link and smoke test; `--json` prints one summary object and never prompts; `--yes` accepts every confirmation and the default for optional prompts (`EDGAR_USER_AGENT` stays empty). Exit codes: 0, 1 (named failure), 2 (bad arguments) |

## portfolio-snapshot

| Script | Usage |
|---|---|
| `brief.py` | `brief.py [snapshot.py flags...] [--no-headlines] [--timeout SECONDS] [--workers N]` — the daily brief: `snapshot.py` with `--events` always on, then the other installed skills' scripts in parallel (watchlist check, market indices and flows, `edgar.py` per single-stock holding, rebalancing `--only-if-breached`, tax report, dividends `--yield-context`, risk stress, journal review and open list, debt picture, spending changes and recurring, ledger summary) turned into `headlines` (`key, code, skill, severity alert|notice|info, symbol, title, detail, as_of, status new|still, ask, url, answer, why`: `url` an https link to the item's page, `answer` one pre-computed sentence of fact, `why` one plain-language sentence of what the item is and why it matters, `ask` a follow-up question) and `coverage` (per source: `skill, script, status ok|skipped|failed, reason, hint, seconds, headlines`), plus `brief_as_of` and `brief_seconds`; `brief-last.json` in the plugin data dir remembers the previous run's keys and risk figures. After sources run, an enrichment phase fills in `answer` for EX_DIVIDEND (from the dividends result already fetched, no call), EARNINGS (one `chain.py SYM --no-history` call for the options expected move) and 10-Q/10-K FILING (one `filing.py SYM --form F --item 1A --diff` call for the risk-factor diff) headlines, at most 6 calls total against one phase deadline equal to the per-source timeout; any failure (missing skill, timeout, bad JSON, the deadline passing) leaves the answer as the extractor set it and never touches flags or coverage. Market's CFTC positioning headline is tightened to index, rates, fx or volatility contracts with at least 26 weeks of history and a plain-language title; spending's new-recurring headline skips everyday categories (Groceries, Dining, Coffee, Transport, Fuel). Skipped, failed and timed-out sources never change the exit code; exit codes are the snapshot's own. Extractors live in `lib/second_opinion/headlines/` |
| `snapshot.py` | `snapshot.py [--account ACCOUNT_ID ...] [--events] [--no-quotes] [--no-news] [--save] [--compare]` — every open account in one run: totals, per-account and per-symbol values, unrealized P&L, day change and 1w/1m change per position, asset classes and an `allocation` block (bonds / US equities / international equities / cash / other from Yahoo fund category, issuer country and name, with the broker's description as the name fallback for institutional share classes; `ASSET_BUCKET_UNKNOWN` lists what fell to other), no-cost-basis share, concentration (position-level HHI plus a `single_stock` view that ignores funds and cash; CONCENTRATED keys off the single-stock view when asset classes are known), sectors (cached in `sector-cache.json` under the plugin data dir, including each ETF/mutual fund's `funds_data` sector weightings and asset-class split, feeding `sector_exposure`'s look-through; an institutional index-fund share class Yahoo cannot identify at all is matched by name to a public proxy ETF — VOO, VXUS, BND or VTI — and looked through using that proxy's sector data, labelled `"SYM (via VOO)"`; `SECTOR_LOOKTHROUGH_PARTIAL` fires when holdings with no sector data plus the unattributed slices of partially described funds together exceed 2% of value, and the flag message names each), movers with up to three dated Yahoo headlines each from the last 7 days (`news`; `--no-news` skips), a weekly-sampled one-year close series per holding (`price_history`) and a profile per holding (`profiles`: name, type, category, country, sector, business summary, website, asset bucket) for the page's detail panel, flags; `--events` adds next earnings / ex-dividend dates; `--save` appends a dated record to `snapshots.json`, `--compare` adds a delta against the most recent earlier saved snapshot. When a broker also reports a money-market core position (e.g. Fidelity's SPAXX) as account cash, it is counted once: backed out of that account's cash (recorded as `cash_adjusted_for_money_market` on the account row) and added into `totals.cash_like`/`cash_like_pct` (settled cash plus money-market fund positions), which the Cash tile and allocation cash bucket now use instead of `totals.cash` |
| `summary.py` | `python summary.py < input.json` — the pure-math half of the snapshot; accepts raw SnapTrade position and balance objects plus optional per-symbol close `history` and `quote_types`; contract in the docstring |
| `render.py` | `render.py [--in snapshot.json] --out page.html` — one self-contained interactive HTML page (stat tiles, accounts, allocation donut by bucket with sector exposure looked through ETF/mutual-fund holdings (falling back to single stocks only for an older snapshot without `sector_exposure`), a one-line intro with a "How to read this page" walkthrough with glossary terms, sortable holdings table with a per-holding detail panel (description, one-year price chart, links) with account filter and search, movers, events, comparison, a Headlines card with a collapsed coverage table when present, flags; light/dark; no external assets) from a `snapshot.py` result, for the Artifact tool; prints `{"out","title","positions","flags","headlines"}`; exit 2 when the input is not a snapshot result. Shared page toolkit in `lib/second_opinion/page.py` |
